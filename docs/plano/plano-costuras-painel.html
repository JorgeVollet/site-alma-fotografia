Plano de evolução · Painel administrativo

Deixar o painel da Alma 100% interligado

Um plano em 4 fases para transformar o painel num organismo único, onde cada ação reverbera nos módulos certos — automaticamente. Para ler, lapidar e aprovar antes de implementar.

O diagnóstico

Onde estamos hoje

Fiz uma auditoria profunda de todo o painel — li cada módulo e mapeei como eles se conectam. A boa notícia: a fundação está certa. A má: ela foi construída em torno de um cliente só.

O painel já é quase um organismo completo, mas tem três pontos que travam o dia a dia:

1. Dois mundos de clientes que não se falam

Quase todos os módulos leem uma lista fixa de clientes de demonstração. Quando você cria um cliente novo, ele vira um "fantasma": não aparece no funil, nem na agenda, nem nos contratos. Só existe na tela de Clientes.

2. As automações estão "presas" no cliente de demonstração

Várias mágicas (liberar fotos, mover no funil) só funcionam para o ensaio ao vivo da demonstração. Para qualquer outro cliente, os botões são decorativos — não disparam as conexões.

3. O site público não alimenta o painel

Quando alguém agenda pelo site, a reserva nasce solta. Não cria cliente, nem galeria, nem projeto. O fotógrafo precisa refazer tudo na mão no painel.

O que JÁ funciona (a base que vamos aproveitar):

  • Contrato assinado → gera conta a receber + move o cliente no funil
  • Quitar uma conta → cria o lançamento no financeiro automaticamente
  • Workflow chega em "entrega" → o cliente vai pra "entregue" no funil
  • Fotos favoritas entregues → viram ensaio no portfólio
  • Agendamento → vira lançamento "Reserva" no financeiro

Ou seja: não começamos do zero. As costuras certas existem — só precisam ser generalizadas (valer pra todos) e estendidas (conectar o site ao painel).

A estratégia

4 fases, da fundação ao topo

Cada fase é testável sozinha e não quebra o que já funciona. Construímos a base primeiro (sem ela, nada novo aparece), depois subimos. Você aprova e testa cada uma antes de seguir.

0
Fundação · a base de tudo

Cliente unificado

Juntar num só lugar todos os clientes — os de demonstração, os que você cria na mão, e os que vierem do site. Hoje eles vivem separados; vamos fazer todos passarem a existir no sistema inteiro.

Hoje: cliente novo não aparece no funil, agenda, contratos. É um fantasma.
Depois: todo cliente percorre o sistema — funil, agenda, financeiro, tudo.

Como faço (sem quebrar nada)

  • Crio uma "lista mestre de clientes" no cérebro do sistema, que junta demo + criados + agendados, mantendo a ordem que cada tela já espera.
  • Cada módulo passa a ler dessa lista mestre, em vez da lista fixa de demonstração. É uma troca pequena e cirúrgica por arquivo.
✓ Como testar: criar um cliente novo na tela de Clientes → ele aparece como card no Funil de vendas. (Hoje não aparece.)

Risco baixo  É uma mudança que só adiciona — não remove nada. O cliente de demonstração continua intacto.

1
Generalizar · vale para todos

Tirar a "Sphor" do código

Fazer as automações funcionarem para qualquer cliente, não só o de demonstração. As mágicas que já existem passam a valer para o estúdio inteiro.

Hoje: liberar fotos / mover no funil só funciona pro cliente ao vivo.
Depois: iniciar edição move pra "produção"; entregar tira do funil — qualquer cliente.

Novas costuras que entram aqui

  • Iniciar edição → o cliente avança sozinho para "Produção" no funil.
  • Liberar download → o cliente vai para "Entregue" no funil + notificação (para qualquer cliente, não só o demo).
✓ Como testar: entregar o ensaio de um cliente qualquer → ele se move no funil automaticamente, sem você arrastar na mão.

Risco médio-baixo  Depende da Fase 0 estar pronta. Decisão a tomar: status detalhado do ensaio (selecionando→editando→pronto) por cliente, ou só o movimento de funil? (recomendo começar pelo funil)

2
Conectar · o maior valor no dia a dia

Site → Painel automático

Quando alguém agenda pelo site, o painel monta tudo sozinho. Essa é a costura que mais economiza tempo do fotógrafo — acaba o retrabalho manual.

Hoje: reserva do site nasce solta. O fotógrafo cria cliente e galeria na mão.
Depois: reserva monta o cliente, o funil e a cobrança — tudo pronto.

O que a reserva passa a criar sozinha

  • Um cliente novo no CRM, já posicionado em "Agendado" no funil.
  • Uma conta a receber do valor restante (total menos a reserva paga).
  • A reserva já cai na Agenda e no Financeiro (isso já funciona).
  • (Opcional) Um contrato em rascunho e uma tarefa "Confirmar ensaio".
✓ Como testar: fazer uma reserva de teste no site → o cliente aparece prontinho no painel (no funil, com a cobrança do saldo já lançada).

Risco médio  O cuidado aqui é não duplicar registros se o cliente voltar passos no agendamento. Uso a mesma proteção que já existe em outras costuras. Depende da Fase 0.

3
Faturar · fecha o ciclo

Notas Fiscais ↔ Financeiro

Conectar a tela de Notas Fiscais aos pagamentos reais. Em vez de uma tela isolada, ela passa a saber o que já foi recebido e está pronto para virar nota.

Hoje: a tela de notas é uma vitrine isolada, não conversa com contas.
Depois: conta recebida → aparece em "pronto para emitir nota", a 1 clique.

A costura

  • O sistema mostra os pagamentos já recebidos que ainda não têm nota, num bloco "Pronto para emitir".
  • Um clique gera a nota (vinculada àquele pagamento), sem redigitar nada.
✓ Como testar: marcar uma conta como recebida → ela aparece na fila de "pronto para emitir nota".

Risco baixo  A emissão fiscal de verdade (que fala com a prefeitura) entra junto com o backend / Focus NFe. Esta fase prepara a conexão; a emissão real vem depois.

Foco

O que NÃO vamos fazer agora (de propósito)

Pra entregar rápido e sem risco, deixo de fora coisas que ninguém pediu ou que dependem do backend. Tudo isso pode entrar depois, se fizer sentido.

  • Emissão fiscal real (XML/PDF na prefeitura) — entra com o backend / Focus NFe.
  • Pagamento real com PIX/cartão de verdade — hoje é simulado; entra com gateway no backend.
  • Lembretes automáticos por prazo e datas que se cruzam entre agenda e workflow.
  • Vários ensaios em paralelo por cliente com status independente — só se você sentir necessidade.
Por que essa disciplina importa: cada coisa a mais é mais risco e mais tempo. Prefiro entregar o painel realmente interligado e sólido com o essencial, do que cheio de funções pela metade. Se faltar algo importante pra Alma, a gente adiciona — é só apontar.
